Summary contract (what the model must return)

FieldRule
languageSet by code, not the model: ≥60% CJK → zh-Hans, else en. Mixed (10–60%) → the dominant script; the user can flip.
headline≤ 12 words / ≤ 20 characters 中文. No colon-led "Summary:".
formatbullets · paragraph · ask. Defaults by type: contract/letter → bullets for terms, paragraph for letters; Other → model decides; low confidence → ask once.
bodyShort: 3–5 bullets or ≤ 80 words. Long: 6–10 bullets or ≤ 200 words. English follows STE: one idea per sentence, < 20 words, active voice, one term per concept, keep finance/legal vocabulary.
keyFactsLabel → value pairs pulled verbatim from the text (parties, dates, amounts, law, deadlines). Never invented: each value must appear in the source; code verifies by substring and drops any that do not.
actions0–4 items the reader must do, each with a date if the text gives one.
groundingModel is told: "Use only the text. If a fact is absent, omit it. Do not guess." Code re-checks key facts and amounts against the extracted fields from Phase 3.

Long documents

StepRule
ChunkSplit on paragraphs; ~2,000 characters per chunk for 中文, ~3,500 for English (Apple's window is ~4k tokens). Never split inside a table row or a numbered clause.
MapEach chunk → 2–4 bullets + key facts, same contract.
ReduceChunk outputs → one final summary. Key facts merged and de-duplicated. Shows "6 chunks" on the card.
CapOver 40 chunks (~100 pages) → summarise first 40, flag "partial" on the card.

Questions

Q1 · Auto-summarise on save for contracts and letters, or only when you tap Summarise? Auto costs ~1–3 s per document on the A19 Pro.
Q2 · When the format is uncertain and the model asks, remember your pick per document type, or ask every time?
Q3 · Mixed-language documents (10–60% CJK): summarise in the dominant script, or produce both languages?
Q4 · Qwen via MLX for long Chinese contracts means a ~2.5 GB one-time model download inside the app. Include it in this phase behind a "Download Chinese model" button, or leave Chinese to Apple's model for now and judge quality on your real contracts first?
